# ADR-008: 최초 온보딩을 네이티브 화면으로 제공

- 상태: Accepted; Android·iOS 실기기 검증 대기
- 기준 Native: `3c3590110910ff77be8a2e9ff0c739e53cbb674b`
- 기준 WebView: `b48e61ff2eca7f90c9c786b562102a2939504ee6` (`pages/onboarding.js`)

## 배경

최초 설치 후 온보딩은 웹 네트워크 요청과 WebView 렌더링을 기다렸습니다. 로그인 전 소개 화면은 서버 데이터나 브리지 호출이 필요하지 않습니다.

## 결정

Android는 Compose, iOS는 SwiftUI의 페이지 컨트롤로 같은 5개 소개 문구를 로컬에서 표시합니다. Android와 iOS는 페이지별 이미지 자산을 선택하며 2~5페이지에 제공된 라이트/다크 아트워크를 사용합니다. 1페이지는 더미 이미지를 유지합니다. 이미지를 문구 바로 위에 배치하고 각 페이지를 5초 후 자동으로 넘깁니다. 사용자가 스와이프하면 해당 페이지부터 시간을 다시 세며 마지막 페이지에서 멈춥니다. 가로 스와이프와 페이지 표시를 제공합니다. 모든 페이지의 `로그인` CTA는 기존 로그인 양식으로 연결합니다. 화면 폭과 높이에 따라 콘텐츠 폭·이미지 공간을 조절하며, 글자가 커지거나 화면이 낮으면 본문을 세로로 스크롤할 수 있게 합니다. 저장 자격증명이 있으면 기존처럼 온보딩을 건너뜁니다.

웹 저장소와 Bridge v1 스키마는 변경하지 않습니다. 롤백이 필요하면 이 변경을 되돌려 이전 WebView 온보딩을 복원합니다.

## 검증

Android 컴파일·JVM 테스트 및 Compose instrumentation의 스와이프/로그인 전환, iOS 시뮬레이터 빌드를 확인합니다. 신규 설치·태블릿·폴더블·Dynamic Type·회전은 기기에서 추가 확인합니다.
