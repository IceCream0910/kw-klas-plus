# ADR-009: 인증 후 설정을 포함한 로그인 퍼널

- 상태: Accepted; 실기기 검증 대기
- 기준 Native: `3c3590110910ff77be8a2e9ff0c739e53cbb674b`
- 기준 WebView: `b48e61ff2eca7f90c9c786b562102a2939504ee6`

## 배경과 결정

신규 수동 로그인은 학번, 비밀번호, KLAS 인증을 각각 한 단계로 보여줍니다. 인증 실패 시 비밀번호 입력으로 돌아가며, 성공 후에는 도서관 출입증 설정(건너뛰기 가능), 앱 잠금 설정과 마감 할 일 알림 설정(각각 건너뛰기 가능), 정책 확인, 완료 화면을 거쳐 홈으로 이동합니다. 기존 저장 자격증명으로 자동 로그인하는 설치는 이 퍼널을 다시 거치지 않습니다.

`login_funnel_status`는 일반 설정에 신규 설치 시 `not_started`, 인증 시작 전 `authenticating`, 인증 성공 후 `setup`, 완료 후 `complete`로 기록합니다. 중단 후 재시작하면 `authenticating`은 비밀번호 입력, `setup`은 출입증 단계로 복귀합니다. Android는 앱 시작 시 상태 키가 없는 설치의 `kwID` 계정 식별자를 확인하여 있으면 `complete`, 없으면 `not_started`로 한 번만 이전합니다. 이전 기록에 실패해 상태가 `null`로 남아도 홈 접근은 차단합니다. iOS는 각 상태 기록의 성공과 재조회를 확인한 뒤 전이하고, 실패 시 홈 진입을 차단합니다. 상태 키가 없는 기존 iOS 설치는 세션 유효성을 확인한 후 `complete`를 기록해 이전합니다. KLAS 인증과 세션 동기화는 공통 유스케이스를 사용하며 새 브리지 메서드는 없습니다. 되돌릴 때에는 이 변경을 되돌려 기존 수동 로그인 화면과 자동 홈 진입을 복원합니다.

Android는 `complete` 이외 상태에서 학사 위젯의 저장 데이터 표시와 갱신을 막습니다. 상태 전환 직후 설치된 위젯을 다시 그려 이전 데이터를 가리고, `complete` 후 갱신을 재개합니다. 도서관 QR 위젯의 Activity·설정 버튼과 직접 `HomeActivity` 진입도 같은 상태 검사로 로그인 퍼널에 돌려보냅니다. `kwID`가 있는 기존 설치는 시작 시 `complete`로 이전하므로 기존 위젯 동작을 유지합니다.

## 동의 및 플랫폼 차이

[토스의 동의 화면 자료](https://static.toss.im/GUARDIANS25/A-3.%20%ED%86%A0%EC%8A%A4%EC%9D%98%20%EB%8F%99%EC%9D%98%EC%84%9C%20%EC%A0%95%EB%B3%B5%ED%95%98%EA%B8%B0_%EC%A0%95%EC%9C%A0%EC%A7%84.pdf)를 참고해 항목별 선택과 전문 보기 동작을 분리합니다. 개인정보 처리방침은 `https://klasplus.yuntae.in/privacy`, 이용약관은 사용자가 제공한 `https://klasplus.yuntae.in/tos`를 엽니다. 두 항목 모두 필수 동의로 표시합니다. 하단 `모두 동의하고 계속` 버튼은 처음부터 활성화하고 누르면 두 항목을 함께 동의한 뒤 완료 화면으로 이동합니다. 완료 상태는 두 항목의 동의를 확인한 후에만 기록합니다. 이용약관 페이지의 실제 내용은 배포 전 별도 확인 대상입니다.

입력 필드·가이드 문구·하단 버튼은 기존 로그인 테마 컴포넌트를 사용합니다. 학번 10자리 입력 시 비밀번호 단계로 자동 이동하며, 위젯 추가 단계는 제공하지 않습니다. 완료 체크 아이콘은 콘텐츠 영역 중앙에 표시하고 진입 및 탭 시 스프링 애니메이션과 햅틱을 제공합니다.

학번 자동 이동은 10자리 미만에서 10자리로 입력값이 바뀐 경우에만 일어납니다. 비밀번호 단계에서 학번 단계로 돌아왔을 때 기존 10자리 값만으로 다시 이동하거나 빈 비밀번호 오류를 표시하지 않습니다. iOS의 뒤로가기 버튼은 iOS 26 이상에서 시스템 `glass` 버튼 스타일을 사용합니다. Android는 출입증 단계에서 전화번호 권한을 요청하지 않고 저장된 `library_phone`을 우선 채우며, 새 번호는 직접 입력합니다. iOS는 저장된 `library_phone`을 우선 채우고 새 번호는 시스템 자동 완성 또는 직접 입력을 사용합니다.

Android 시스템 뒤로가기와 iOS 화면 가장자리 제스처는 이전 단계가 있을 때 같은 단계 이동 함수를 사용합니다. 인증 중에는 이동하지 않고 인증 이후 출입증 단계에서는 이전 인증 단계로 돌아가지 않습니다. 완료 단계에서는 약관 단계로, 약관 단계에서는 알림 단계로, 알림에서는 앱 잠금 단계로, 앱 잠금에서는 출입증 단계로 돌아갈 수 있습니다.

출입증 정보 저장이 실패하면 도서관 단계의 입력을 유지하고 오류를 표시합니다. iOS Keychain 기록 실패는 결과 콜백으로 전달하며, 설정 화면에서도 성공으로 표시하지 않습니다. 저장된 퍼널 상태가 `setup`이 아니거나 완료 조건이 어긋난 경우에는 두 플랫폼 모두 오류를 표시하고 홈 진입을 차단합니다.

출입증 전화번호 입력은 숫자만 화면에 남깁니다. 기존 설치에서 하이픈이 있는 번호가 남아 있어도 도서관 HTTP 요청의 `tel_no`는 숫자만 전송합니다. `LibraryHttpGatewayTest`는 하이픈이 있는 입력이 숫자만 담긴 `tel_no`로 전송되는지 확인합니다.

## 검증

기준 Native `107c6ff026f319a4d4f5236b5b39f4b18001567d`와 위 WebView 버전에서 브리지 계약은 변경하지 않았습니다. CI [run 36254494569](https://github.com/IceCream0910/kw-klas-plus/actions/runs/36254494569)에서 Android와 iOS 테스트가 통과했고 iOS 앱 테스트 181개가 성공했습니다. 리뷰 후 출입증 저장 실패와 퍼널 단계 불일치에 대한 오류 처리를 추가했습니다. 후속 변경은 로컬 `:shared:iosSimulatorArm64Test`, `:shared:testAndroidHostTest`, `:androidApp:testDebugUnitTest`, Android 계측 테스트 컴파일과 iOS 앱 전체 182개 테스트로 확인했고, 최종 상태 재조회 보강 뒤 인증 컨트롤러 테스트 16개를 다시 통과했습니다. 최종 CI 검증은 대기 중입니다. Android 전체 계측 테스트는 로컬 API 37 에뮬레이터에서 19개 통과 후 비디오 전환 테스트 도중 에뮬레이터가 오프라인이 되어 중단됐습니다. 사용자가 최종 동작 테스트를 수동으로 진행합니다. 추가로 KLAS 인증 후 출입증·동의 퍼널을 끝내기 전 학사 위젯이 비어 있는지, 도서관 QR 위젯과 그 설정 버튼이 홈 대신 퍼널을 여는지, 완료 후 위젯 데이터가 다시 갱신되는지 확인합니다. 신규 로그인/실패/중단 후 재시작/출입증 건너뛰기/두 약관 전문 보기·동의/홈 진입 및 도서관 Keychain/Keystore 저장은 수동 검증 대상입니다.

## 마감 할 일 알림 단계 추가 (2026-10-03)

최종 순서는 아래 추천 설정 순서 변경을 따릅니다. 알림 설정은 기존 Native 권한 bottom sheet를 재사용하며 setup 계정에는 설정 저장만 허용합니다. 홈·조회·발송·위젯은 complete gate를 유지하고 기존 complete 사용자에게 퍼널을 다시 요구하지 않습니다.

이번 변경 기준은 Native `7faa2f8`, WebView `bc5a173`이며 Web 브리지 변경은 없습니다. 공통 Android 289개·iOS Simulator 314개, Android JVM 36개 테스트와 소스 경계 검증 및 Debug APK 빌드가 통과했습니다. Android 로그인 화면 계측 테스트 3개는 직접 AndroidJUnitRunner 실행으로 통과했습니다(Gradle Orchestrator XML은 0개를 기록하여 직접 실행 결과를 근거로 사용). iOS Simulator 앱 빌드는 통과했습니다. 무서명(`CODE_SIGNING_ALLOWED=NO`) XCTest는 기존 세션 만료 테스트의 Keychain 정리에서 Kotlin 예외가 Swift 경계를 넘어 SIGABRT로 종료됐고, 후속 재실행에는 Code=3 오류가 표시됐습니다. 시뮬레이터용 ad-hoc 서명(`CODE_SIGN_IDENTITY=-`)으로 재실행해 인증 컨트롤러 테스트 전체가 통과했고, 기존 세션 만료 테스트와 새 알림 단계 테스트도 통과했습니다. Keychain을 사용하는 XCTest는 서명을 유지하며 무서명 옵션은 빌드 확인에만 사용합니다. 실제 신규 로그인과 OS 권한 허용·거부·시스템 설정 복귀·알림 발송의 양 플랫폼 수동 검증은 남아 있습니다.

## 추천 설정 순서 변경 (2026-10-03)

이 시점에는 두 선택 설정을 한 페이지에 추천했습니다. 최종 순서는 아래 개별 설정 단계 결정을 따릅니다. 추천 페이지의 두 항목은 각각 기존 Native 설정 화면/권한 시트로 연결하고, 설정 후 같은 페이지에서 완료 상태를 표시합니다. 계속 또는 건너뛰기로 약관에 진입합니다. 선택 설정 여부와 관계없이 약관 동의 전에는 complete를 기록하지 않습니다. 앱 잠금은 기존 보안 저장·비밀번호 확인·생체인증 경로를 재사용하며, iOS setup에서는 추천 페이지가 요청한 set/change 화면만 허용하고 자동 unlock 화면이나 홈을 열지 않습니다.

순서 변경 검증: Android Debug 빌드·JVM 테스트 36개와 로그인 화면 직접 계측 테스트 3개가 통과했습니다. 서명된 iOS Simulator 실행에서 인증 컨트롤러 17개 및 앱 잠금 테스트 4개가 통과했습니다. 추천 건너뛰기 후 약관 필수 경로와 setup에서 명시적 set/change만 표시하는 경계를 확인했습니다. 실제 계정 로그인·PIN 설정·생체인증·OS 알림 권한 및 설정 복귀의 양 플랫폼 수동 확인은 남아 있습니다.

## 개별 설정 단계 및 시각 안내 (2026-10-03)

앱 잠금과 마감 알림은 별도 선택 단계로 분리합니다. 로그인→출입증→앱 잠금→마감 알림→약관→완료 순서를 따릅니다. 각 퍼널 단계는 원형 배경·애니메이션 없는 아이콘과 상단 색상→투명 움직이는 그라데이션 배경을 사용하고 시스템의 모션 감소 설정에서는 움직임을 줄입니다. 알림 권한 시트는 상단 종 아이콘 없이 타이틀·설명과 알림 예시를 사용합니다. 시트 진입 시 이미 authorized/provisional인 경우 권한 요구 화면 없이 설정을 저장하고 완료 안내를 표시합니다. 완료는 자동으로 닫지 않으며 짧은 동작 설명과 별도 닫기 버튼을 제공합니다. 미허용은 기존 명시적 CTA 및 거부·저장 실패 경로를 유지합니다.

설정 완료 후 이동: 앱 잠금 저장 성공으로 설정 화면이 닫히면 자동으로 알림 단계로 이동합니다. 온보딩 알림은 저장 성공 즉시 배경 퍼널을 약관 단계로 진행하되 완료 시트는 유지합니다. 온보딩·설정 페이지 모두 별도 닫기 버튼으로 시트를 닫습니다. 취소·거부·저장 실패 및 유효하지 않은 setup 상태에서는 자동 진행하지 않습니다.

온보딩에서 이미 앱 잠금/마감 알림이 활성화된 단계는 상태 확인 후 자동 진행합니다. 미허용 권한, 취소, 저장 실패는 자동 진행하지 않으며 약관은 계속 필수입니다.

시트 설명은 타이틀 바로 아래에 모으고 그 아래에 알림 예시 그래픽을 배치합니다. 권한 CTA와 나중에 버튼의 간격은 16dp/pt입니다. 출입증의 저장/건너뛰기 간격은 각 플랫폼 앱 잠금·알림 단계와 통일합니다. 온보딩 잠금 설정은 기존 PIN이 있는 변경 경로도 성공 후 잠금을 활성화하며, 취소에는 활성화나 퍼널 이동을 하지 않습니다.
